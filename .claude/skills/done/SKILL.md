# Завершение дневной задачи

## Текущее состояние

Git status:
!`git status -s`

Git diff (статистика):
!`git diff --stat`

Недавние коммиты:
!`git log --oneline -5`

## Инструкции

Ты завершаешь дневную задачу AI Challenge. Выполни шаги по порядку:

### 1. Определи текущий день

- Если передан аргумент `$ARGUMENTS` — используй этот номер дня
- Иначе — прочитай `TASKS.md`, найди последний `## Day N` без ✅ в заголовке

### 2. Проанализируй изменения

- Прочитай `git diff` (staged + unstaged) чтобы понять что было сделано
- Прочитай `git log` с последнего тега/коммита предыдущего дня
- Определи: какие файлы добавлены/изменены, какие фичи реализованы, какой ключевой код написан

### 3. Обнови `TASKS.md`

Заполни секцию текущего дня по шаблону из предыдущих дней:

```markdown
## Day N — Название ✅

**Assignment:** (скопируй из секции или напиши по смыслу)

**What was built on top of previous day:**
- (конкретные изменения, новые файлы, новые возможности)

**Key code:** `функция1()`, `функция2()`, `тип`
```

Сохраняй стиль предыдущих записей в TASKS.md — лаконично, конкретно, с именами функций.

### 4. Обнови `CLAUDE.md`

Прочитай текущий `CLAUDE.md` и добавь:
- Новые файлы в секцию **Project structure** (если появились)
- Новые CLI флаги в таблицу **CLI flags** (если появились)
- Новые chat-команды в таблицу **Chat commands** (если появились)
- Новые решения в **Key decisions** (если есть значимые архитектурные решения)
- Обнови описания существующих файлов если их назначение изменилось

НЕ добавляй то, что уже есть. НЕ удаляй существующую информацию.

### 5. Покажи пользователю что будет закоммичено

Выведи:
- Список файлов для коммита
- Предлагаемое коммит-сообщение
- Дождись подтверждения

### 6. Проверь `.gitignore`

- Посмотри `git status` и `git diff` — есть ли новые файлы/директории, которые НЕ должны попасть в репозиторий (кэши, артефакты сборки, конфиги с секретами, node_modules, временные файлы и т.д.)
- Прочитай `.gitignore` и добавь недостающие паттерны если нужно

### 7. Коммит и пуш

- `git add` нужных файлов (конкретные файлы, не `git add .`)
- `git commit` с описательным сообщением формата: `day N: краткое описание`
- `git push`
